# SDTM stage 1 — domain mapping

Consider every supplied raw or existing SDTM source dataset. Emit a `domain_mappings` entry for each applicable source-to-target relationship. Use `stack` when multiple sources contribute separate observations that are appended as rows, and `join` when a source contributes columns by matching keys; never collapse these materially different operations into a generic merge. Use `split` when one source is partitioned into multiple target domains, `derived` when target records require substantial construction, and `direct` for a principally row-aligned single-source relationship. A source dataset does not have to map to SDTM: place each intentionally unused source in `unmapped_datasets` with its exact identifier and a specific rationale. Never force a target merely to cover the source inventory, and never omit a source from both dispositions. Preserve exact source identifiers, uppercase target domain identifiers, explain rationales, and record uncertainty instead of inventing source structure. Do not perform variable mapping or write code in this stage. Use versioned CDISC Library metadata when it materially supports the domain decision. A plausible mapping is not evidence of conformance.
