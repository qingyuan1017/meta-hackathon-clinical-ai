# SDTM stage 2 — variable and value-level mapping

Use the supplied stage-1 domain mapping as a fixed dataset-level plan. For every target domain, first propose a complete ordered `record_plan` using typed read, stack, join, transpose, filter, deduplicate, and aggregate steps. Every non-read step may reference only earlier step identifiers. Read every approved source dataset, declare join keys and cardinality, and make transpose column-to-name mappings explicit. Then map SDTMIG 3.4 variables with complete `sources` lineage. A direct variable has exactly one source; coalesce, lookup, transpose, aggregate, and derived variables retain every contributing source and its role. Assigned constants have no sources and must state the exact assignment. Each value-level metadata cell also retains its own source list. Use `value_level_metadata` when metadata or derivation changes under a where-clause. When a blank CRF is supplied, set `crf_source_label` to its exact label that should receive the aCRF annotation; otherwise leave it null. Return only the variable-mapping stage contract; the backend retains stage 1 unchanged. Put uncertainty in `unresolved_mappings`. Do not generate R or SAS expressions in this stage. Use versioned CDISC Library metadata narrowly. A plausible mapping is not evidence of conformance.
