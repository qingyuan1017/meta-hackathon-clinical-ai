# SDTM stage 2 — variable and value-level mapping

Use the supplied stage-1 domain mapping as a fixed dataset-level plan. Map SDTMIG 3.4 variables with complete `sources` lineage and only minor per-variable derivation metadata. A direct variable has exactly one source; coalesce, lookup, transpose, aggregate, and derived variables retain every contributing source and its role. Assigned constants have no sources and must state the exact assignment. Each value-level metadata cell also retains its own source list. Use `value_level_metadata` when metadata or derivation changes under a where-clause.

For wide-to-long findings such as LB, VS, or EG, build a coherent matrix rather than putting all analyte detail only under `--ORRES` or `--STRESN`. Use the exact same normalized `--TESTCD = 'value'` where-clause set across every slice-dependent target variable. Put test codes in `--TESTCD` cells, test names in `--TEST` cells, original results in `--ORRES`, original units in `--ORRESU`, standard character/numeric results in `--STRESC`/`--STRESN`, standard units in `--STRESU`, and ranges or flags in their matching target-variable cells. Every multi-source transpose variable must partition all top-level sources into its VLM cells; a source may not remain only in the flattened variable lineage. Preserve the source variable that supports assigned test metadata so every cell remains traceable. Do not invent a VLM cell when the source is already a genuinely long-form test/value structure.

When a blank CRF is supplied, add every exact question label that should receive this target variable to `acrf_annotations`; one variable may have multiple annotations. Use `DOMAIN.VARIABLE` as each annotation's default `mapping_text`. Keep the legacy `crf_source_label` null. Without a blank CRF, leave both annotation fields empty. Return only the variable-mapping stage contract; the backend retains stage 1 unchanged. Put uncertainty in `unresolved_mappings`. Do not generate a `record_plan` or target-variable R/SAS expressions in this stage; record construction and executable code belong to rule augmentation. Use versioned CDISC Library metadata narrowly. A plausible mapping is not evidence of conformance.
