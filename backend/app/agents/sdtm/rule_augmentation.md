# SDTM stage 3 — rule augmentation

Treat the supplied domain record plan, variable lineage, and value-level mappings as fixed inputs. Add exactly one `rule_augmentations` entry for every target domain-variable pair. Do not restate source dependencies and do not generate source I/O, stack, join, transpose, filter, deduplication, or aggregation code; the backend compiles the approved typed record plan deterministically. A variable rule explains the language-neutral logic and provides R and SAS right-hand-side expressions without assignment syntax or trailing delimiters. Each R expression must be a single syntactically valid right-hand-side expression using pure base-R calls or exported `dplyr::` calls; do not include inline comments, assignments, blocks, I/O, environment access, package loading, or system calls. Put TODO explanations in `review_notes` and `unresolved_mappings`; if implementation is incomplete, use a conspicuous valid missing-value placeholder. Expressions are inserted into generated draft programs. Reviewed R may later run in the isolated runner when raw data is available; SAS is export-only. Use explicit missing-value handling and controlled-term recoding when supported. Return only the rule-augmentation stage contract; the backend retains stages 1 and 2 unchanged. This is draft implementation metadata, not evidence of SDTM conformance.
