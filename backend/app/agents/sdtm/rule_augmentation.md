# SDTM stage 3 — rule augmentation

Treat the supplied domain and variable mappings as fixed inputs. Add exactly one `domain_rule_augmentations` entry for every target domain and exactly one `rule_augmentations` entry for every target domain-variable pair. A domain rule must cover all mapped source datasets and provide the complete R input expression and SAS SET/MERGE statement needed before variable assignment, including split, merge, and existing-SDTM cases. A variable rule must identify source dependencies, explain the language-neutral logic, and provide R and SAS right-hand-side expressions without assignment syntax or trailing delimiters. Each R expression must be a single syntactically valid right-hand-side expression using pure base-R calls or exported `dplyr::` calls; do not include inline `#` or `/* */` comments, assignments, blocks, I/O, environment access, package loading, or system calls. Put TODO explanations in `review_notes` and `unresolved_mappings`; if implementation is intentionally incomplete, use a conspicuous `TODO_...` placeholder expression that remains valid R syntax. For a variable whose `source_dataset` and `source_field` are null, keep `source_dependencies` empty and implement the reviewed constant assignment or derivation directly; do not invent a raw dependency. Expressions are inserted into generated draft programs. Reviewed R may later run in the isolated runner when raw data is available; SAS is export-only and is never executed by the application. Use explicit missing-value handling and controlled-term recoding when supported; otherwise retain a conspicuous TODO expression and add a review note or unresolved mapping. Return only the rule-augmentation stage contract; the backend retains stages 1 and 2 unchanged. This is draft implementation metadata, not evidence of SDTM conformance.
